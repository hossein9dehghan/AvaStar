# استقرار روی Vercel

این نسخه از Next.js استاندارد استفاده می‌کند؛ به Vinext، Worker، حساب ChatGPT یا ابزارهای داخلی Sites وابستگی اجرایی ندارد.

## دو پروژه، یک دامنه و یک ساب‌دامین

1. ریپازیتوری `hossein9dehghan/AvaStar` را Import کنید. پروژه اول Root Directory برابر `apps/web` دارد.
2. همان ریپازیتوری را دوباره Import کنید. پروژه دوم Root Directory برابر `apps/design-system` دارد.
3. در هر دو، Framework برابر Next.js و Node.js برابر 22.x یا نسخه پشتیبانی‌شدهٔ جدیدتر باشد. pnpm از `packageManager` و lockfile ریشه تشخیص داده می‌شود.
4. دسترسی به فایل‌های خارج از Root Directory را روشن بگذارید. Build هر اپ `pnpm build` است و فایل‌های عمومی را از `packages/assets` و `packages/theme` آماده می‌کند.
5. در هر دو پروژه `NEXT_PUBLIC_SITE_URL=https://YOUR_DOMAIN` را تنظیم کنید. پیش از Build آدرس واقعی را وارد کنید؛ متادیتای SEO و لینک‌ها در زمان Build از این مقدار استفاده می‌کنند.
6. آدرس دیزاین سیستم به‌طور پیش‌فرض `https://design.YOUR_DOMAIN` خواهد بود. در صورت انتخاب نام دیگری، `NEXT_PUBLIC_DESIGN_SYSTEM_URL` را در هر دو اپ تنظیم کنید.
7. در Settings → Domains پروژه اول دامنه اصلی و در پروژه دوم ساب‌دامین `design.YOUR_DOMAIN` را اضافه کنید.
8. در پنل DNS دقیقاً رکوردهای A/CNAME و در صورت لزوم TXT نمایش‌داده‌شده توسط Vercel را وارد کنید. مقدار رکورد را از پروژه خودتان بردارید؛ این سند مقدار ثابت یا دامنه تأییدنشده تجویز نمی‌کند.
9. بعد از تأیید DNS، HTTPS و لینک رفت‌وبرگشت لندینگ/دیزاین سیستم را بررسی کنید. تغییر متغیرهای `NEXT_PUBLIC_*` به Deploy جدید نیاز دارد.

برای اولین بررسی بدون دامنه، URL موقت پروژه دیزاین سیستم را در `NEXT_PUBLIC_DESIGN_SYSTEM_URL` هر دو پروژه بگذارید. هنگام اتصال ساب‌دامین، آن را جایگزین کنید. محیط Preview را با آدرس‌های موردنظر خودش پیکربندی کنید؛ URL سایت قبلی در کد ثابت نشده است.

## ذخیرهٔ درخواست‌های مشاوره

نسخه اصلی از Cloudflare D1 استفاده می‌کرد. آداپتر این نسخه همان schema را از REST API در Vercel استفاده می‌کند:

| متغیر فقط سمت سرور          | مقدار                                    |
| --------------------------- | ---------------------------------------- |
| `CLOUDFLARE_ACCOUNT_ID`     | شناسه حساب Cloudflare خودتان             |
| `CLOUDFLARE_D1_DATABASE_ID` | شناسه دیتابیس D1 قابل دسترسی خودتان      |
| `CLOUDFLARE_D1_API_TOKEN`   | توکن محدود به حساب مربوط با مجوز D1 Edit |

SQL فایل `database/001-guidance-requests.sql` را در دیتابیس اجرا کنید. این متغیرها فقط در پروژه `apps/web` لازم‌اند؛ آن‌ها را با پیشوند `NEXT_PUBLIC_` تعریف نکنید و در Git قرار ندهید. دیتابیس مدیریت‌شدهٔ نسخهٔ Sites و داده‌های آن خودکار به حساب شما منتقل نمی‌شوند. برای مهاجرت دادهٔ قبلی، دسترسی و انتقال مستقل لازم است.

API اعتبارسنجی ورودی، کنترل Origin، محدودیت درخواست بر اساس راه تماس، پارامترهای SQL و شناسهٔ تکرارناپذیر را حفظ می‌کند. در خطای سرویس یا نبودن تنظیمات، دادهٔ ثبت‌نشده موفق گزارش نمی‌شود. اتصال واقعی به D1 باید پس از تنظیم اطلاعات حساب با یک درخواست آزمایشی بررسی شود.

## بررسی پس از Deploy

- `/fa` و `/en` در لندینگ و دیزاین سیستم باز شوند.
- لینک فوتر به ساب‌دامین برود؛ مسیرهای قدیمی `/fa/design-system` و `/en/design-system` نیز منتقل شوند.
- فونت‌ها و لوگوها، تم روشن/تیره و نمونه‌های پنل بررسی شوند.
- لندینگ تیره بماند؛ گزینه کاهش حرکت چرخش سیاره‌ها را متوقف کند.
- فرم مشاوره پس از تنظیم دیتابیس یک رسید واقعی بگیرد.
- دیزاین سیستم `noindex` دارد؛ لندینگ sitemap و canonical مبتنی بر دامنه واقعی دارد.

منابع رسمی: [Monorepos در Vercel](https://vercel.com/docs/monorepos)، [اتصال دامنه](https://vercel.com/docs/domains/working-with-domains/add-a-domain)، [D1 Query API](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/).
